## 2. 이번 세션(2026-10-01)에서 한 일 — 5개 트랙

### 트랙 1 — 브릭 근본 원인 특정 (RC-1)

**증거 사슬(전부 오프라인 재현 가능):**

1. 플래시된 fwsc 안 `app.bin` SHA-256 `5caaaf32…` == 현재 SDK 트리의
   `linux-build/fw-AC79_AIoT_SDK/cpu/wl82/tools/app.bin`
2. 그 바이너리의 `sdk.map`: `.data @0x04000000`, `.bss @0x040009A0`,
   `_HEAP_END = 0x041FFFE0`
3. 링커 선택은 `cpu/wl82/sdk_ld.c`가 `CONFIG_NO_SDRAM_ENABLE` 유무로 결정
4. `demo_hello` vs `demo_ota` 보드 Makefile `DEFINES` diff = **정확히 한 줄**
   (`-DCONFIG_NO_SDRAM_ENABLE` 누락)
5. 정상 v15 앱은 `0x04000000`을 쓰지 않는 SFC/XIP 빌드
6. SDK 동봉 `AC7911B8_Datasheet_V1.0.pdf` §4: 부품 번호 = `AC7911`+①+②,
   **②가 메모리 코드 한 자리** — `8` = 8 Mbit Flash, SDRAM/PSRAM은 `A/B/C/D`.
   장치 마킹 `C108221-11B8` + 실측 1 MiB가 정확히 코드 8과 일치

**프로세스 원인(RC-4)**: 오프라인 게이트를 통과한 산출물(NO_SDRAM 포함 빌드)과
실제 플래시한 산출물(누락 빌드)이 달랐고, **링크 맵을 보는 게이트가 없었다.**

→ `baselines/v15/analysis/usb-flash-readiness/README.md` §1–2

### 트랙 5 — v15 ↔ v16 diff (016 복원·복호화 성공)

- **막힌 원인**: 016은 UFW 안에서 **flash.bin 시작이 `0x400` → `0x410`** 으로
  이동(16 B). 고정 오프셋 가정이 실패 원인이었다.
- 해결: 후보 오프셋마다 복호화해 JLFS 이름 `app_area_head`를 찾는 방식 →
  `tools/smk37_fwsc_app_extract.py`
- **경로 검증**: 015를 이 경로로 디코드하면 `36fe8299…` = 기존 정답과 일치

| | v15 | v16 |
|---|---|---|
| app.bin 크기 | 617,012 | **619,704 (+2,692)** |
| 디코드 SHA-256 | `36fe8299…`(정답 일치) | **`0f64fbf6ffc454ee…`** |
| flash.bin payload 오프셋 | 0x400 | **0x410** |

- **삽입 지도**(v15 함수 684개 앵커): 대부분 구간은 순수 shift(+2494/+2506)이고
  실제 변경은 소수 지점. 그 지점이 우리 핵심 위치와 겹친다 —
  **`0x0201C5EC`(Note On/Off 디스패처) 앞뒤**, **`0x0201E13E`(S1C
  producer/selector) 부근**, `0x02007552..` 구간 −12 B 삭제.
- **USB 디스크립터 변경**: `0x02057B53 → 0x02058553`(+0xA00),
  **PID `0x4B4D` → `0x344B`**, iManufacturer 1→0.
- **신규 UI 문자열**: `Local-`(`0x0205E2D3`), `USB Rec-`(`0x0205E32A`) — v15에 없음.
  같은 블록에 **`Key Chn-`, `Pad Chn-`, `Keys Channel-`, `Pads Channel-`** →
  **벤더가 "소스별 채널" 구조와 Local Control을 이미 정식 구현해 두었다.**

→ `baselines/v15/analysis/v15-vs-v16-app-diff-2026-10-01/README.md`

| 사실 | 근거 |
|---|---|
| 칩 실장 flash = **1 MiB**, `>= 0x100000` 접근 불가 | 1 MiB 덤프 A/B, flash id `0x856014` |
| **AC7911B8 = 8 Mbit Flash 변형**(SDRAM/PSRAM 아님) | SDK 동봉 데이터시트 §4 + 마킹 `C108221-11B8` |

## 5. 하지 말 것 (하드 게이트)

1. **016 패키지를 설치하지 마라.** v15 기반 복구·복원 자산이 전부 무효화되고,
   016용 복원 자산이 아직 없다.
2. **부트 영역(`0x0..0x4000`)을 쓰지 마라.** 어떤 패키지로도 재구성되지 않는다.
3. **복구 자산(강제 로더 + 1 MiB 덤프 A/B + 롤백 fwsc)이 이번 세션에서 동작
   확인되기 전에는 쓰지 마라.**
4. **`0x04000000` 배치 금지** — `tools/check_sdk_app_layout.py`가 강제한다.
5. **미해독 구간을 free space로 승격하지 마라.** M09가 그 추론으로 장치를 잃었다.
6. 관리자 승인 없이 실기 쓰기 금지. read-only(`device-info`, 덤프)만 자유.

## 8. 알려진 함정 / 환경 이슈

1. **`tools/smk37_v15_app_patch.py`를 Python 3.14에서 import하면 실패한다**
   (`@dataclass` 처리에서 예외, 트레이스백 후반부 미확보). 이번 세션은 같은
   알고리즘을 독립 구현(`tools/smk37_fwsc_app_extract.py`)해 우회했다.
   **다음 세션에서 원인 확인 + 도구 수정 필요** (기존 패키징 경로가 막혀 있을 수 있음).
2. **flash.bin 오프셋을 상수로 가정하지 마라** — 015는 `0x400`, 016은 `0x410`.
3. **JLFS 헤더는 cipher다.** `decrypt(fl, 0x4000, ...)`로 풀면 `app_area_head`가
   평문으로 나온다(블록 키 = `0x980F ^ ((addr-0x4000)>>2)`).
4. **파일 대부분이 git에서 untracked 상태**다(`docs/handoff.md` 포함). 커밋 정책을
   먼저 확인하고, 커밋 시 이번 산출물이 누락되지 않게 하라.
5. 016의 삽입 지도는 **24 B 앵커 기반 추정**이다. `0x02023C42` 구간의 `+11156`은
   오일치 가능성이 높다. 함수 경계 확정은 016 리스팅이 필요하다.
6. 016 패키지는 **커뮤니티 저장소에서 받은 것**이며 벤더 서명 검증이 아니다.
