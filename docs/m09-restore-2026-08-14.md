# M09 v15 Restore - 2026-08-14

## Incident

M09 (SMK-37 Pro, WL82) completely bricked after S1C5 OTA write failure.
USB dead, device unresponsive except WL82 UBOOT1.00 USB Device on Windows.

## Root Cause

S1C5 modified firmware corrupted during OTA write (app_area_head or app.bin
integrity check failed at boot). Device entered boot loop with no USB
enumeration from the AC79 app, only the WL82 bootloader.

## Recovery Procedure

### Step 1: Flash Dump (Windows, forced upgrade tool)

```
Device: \.\PHYSICALDRIVE5 (WL82 UBOOT1.00 USB Device, 1MB)
Tool:   Jieli V4 forced upgrade (wl82loader.bin + flash.bin)
Result: m09-flash-20260815.bin (SHA256 53ebcd7a...)
```

### Step 2: Diff Analysis

Compared M09 dump vs v15 stock `flash.bin` (SHA256 22255a7e...):

| Range | Sectors differ | Action |
|---|---:|---|
| 0x00000..0x03FFF (boot header) | 0 | Skip (device-specific) |
| 0x04000..0x042FF (JLFS header) | 1 | **Write** (3628 bytes) |
| 0x04300..0x04FFF | 0 | Skip |
| 0x05000..0x9A000 (app area) | 150 | **Write** |
| 0x9A001..0x9BFFF (tail) | 0 | Skip |
| **Total** | **151** | |

### Step 3: Restore Bundle

Created `build/SMK37Pro-WL82-M09-rollback-v1/`:
- `recovery-sectors/manifest-m09-v15-full-diff-20260815.json`
- `recovery-sectors/v15-full/stock-sector-*.bin` (151 files)
- `restore/smk37_wl82_m09_v15_restore.py`
- `restore/run-m09-restore.ps1` (one-click auto-detect)
- `assets/wl82loader.bin`
- `tools/windows_scsi_transport.py`

### Step 4: Execute (Windows, one-click)

```powershell
powershell -ExecutionPolicy Bypass -File .\SMK37Pro-WL82-M09-rollback-v1\restore\run-m09-restore.ps1
```

Auto-detected PHYSICALDRIVE5, ran self-test PASS, wrote 151 sectors.

## Result

- M09 restored to stock v15 firmware
- Device boots normally, reports firmware v1.10
- All functionality confirmed working
